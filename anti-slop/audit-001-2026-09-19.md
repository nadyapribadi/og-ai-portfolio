# Anti-slop audit 001: demo1 Streamlit UI

Scope: `demo1_doc_intelligence/src/app.py` (the CSS block and every rendered
string) and `config.py` (sidebar labels, cards, questions).
Method: antislop core (purpose test, rule tiers), antislop-ui (visual),
antislop-human (contrast). Contrast measured with the skill's own checker,
`python3 contrast-check.py <fg> <bg>`, not by eye.
Mode: **2 (audit)**. Nothing is changed until specific finding numbers are
approved.

## Findings

Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM,
Quality Lock = LOW.

### HIGH

1. **R-25**: `--text-muted` `#484f58` measures **2.09:1** on the sidebar
   (`#161b22`) and **2.28:1** on the page (`#0d1117`), against the 4.5:1 AA
   requirement. It is used for `.sidebar-label` ("Document Sources", "Try
   asking"), "POWERED BY", `.index-badge`, `.empty-hint`, the inactive clear
   button, and the `⚠️ Answers may be incomplete. Verify against original IOGP
   documents.` disclaimer. The safety sentence of the whole app is the least
   readable text in it.
2. **R-25 / WCAG 1.4.11 (non-text)**: component boundaries sit at **1.55:1**
   (`--border` `#30363d` on `#0d1117`) and **1.65:1** (button border `#3d4451`
   on its own fill `#1c2128`), against the 3:1 required for a control's
   boundary. The chat input's only visible boundary is that border.
3. **R-02 (Hard Gate: em dash forbidden in any text)**: em dashes are
   rendered in `DOCUMENT_SOURCES` (5 entries), in two capability-card
   descriptions, and in the excerpt renderer, whose literal source is
   `st.markdown(f"**[{i}]** \`{friendly}\` \u2014 Page {page}")`.
4. **R-32 / R-03**: the CSS sets `#MainMenu`, `footer`, and `header` to
   `visibility: hidden`. Streamlit's header carries the sidebar toggle, so on a
   narrow viewport the sidebar (document list, sample questions, clear button)
   can become unreachable, and the app menu (rerun, theme, settings) is gone.
   Needs a keyboard and a 375px check; today it is an unverified accessibility
   regression.

### MEDIUM

5. **R-04 / emoji as decoration**: 16 distinct emoji in UI text: 🛢️ twice in
   the title, 📚 💡 📐 ✅ 🇮🇩 📄 🔍 🗑️ ❌ ⚠️ 🔎 📋 🦺 📊 ⚙️ across sidebar
   labels, buttons, badges and cards. No written relevance, and emoji competes
   with the content for attention.
6. **Readability (R-25 spirit / C-4)**: nearly every label, caption, badge and
   sidebar item is 0.62–0.78rem (≈9.9–12.5px); only body text (0.875rem) and
   titles are larger. Small size plus wide tracking plus low contrast is the
   compound that makes the UI tiring.
7. **R-01 / R-13 (dose caps)**: the amber accent appears in nine places
   (title span, badge text, badge border, hover fill, button hover border,
   chat-input focus border, focus glow shadow, loading text). Accent and glow
   are spread rather than concentrated on one focal point.
8. **R-06**: IBM Plex Mono is used for uppercase, 0.1em-tracked micro-labels
   and every caption. Mono as an aesthetic, at the size where mono is hardest
   to read.
9. **R-13 / R-31**: the green `●` beside the document count is a status glyph
   marking no state.
10. **R-14**: the four capability cards share identical size, padding and
    emoji icon, so a flagship capability and a footnote carry the same weight.

### LOW

11. **R-21**: dark-only, no user choice, on a text-heavy reading product
    (specification clauses and verbatim quotes). Dark is a decision, and the
    reason is not written down anywhere.
12. **R-29**: four chromatic colours (amber, green, red, blue) plus neutrals.
    Green/red are semantic and defensible; blue for source tags competes with
    the amber accent for the same job.
13. **R-19**: answers stream word by word at 0.018s per word, motion that
    delays reading with no UX purpose; the model has finished long before.
14. **R-05 / focal point**: every screen's empty state is the same 2x2 card
    grid; there is no single element that is clearly the most important.
15. **Verify, not asserted**: buttons are restyled with `!important`
    backgrounds and borders, which may suppress Streamlit's default focus ring.
    A keyboard pass (Tab through every control, screenshot the focus) is needed
    before this can be called PASS or FAIL.

## Options considered

**A. Keep the console, fix the ink.** Raise `--text-muted` to a passing token,
raise `--border` to 3:1, bump the type scale, remove emoji and em dashes,
concentrate the accent. Small diff, identity intact, low risk. Does not answer
"this is tiring to look at" beyond the measurable part: the surface stays dark
and dense for long-form reading.

**B. Document reader, light first.** Paper-like surface, ink-dark text, amber
as the single accent, excerpts as real blockquotes with source chips, sidebar
as a document index. Best reading ergonomics and the most contrast headroom,
matching the people who actually use it (site and contracts engineers reading
specs). Costs a full CSS replacement and softens the "oil and gas console"
character.

**C. Native theme plus a thin CSS layer.** Move the palette into
`.streamlit/config.toml` `[theme]`, keep CSS only for the app-specific
components (chat bubbles, citation chips, cards). Fewer overrides, widgets keep
their own focus and disabled styling, less to maintain across Streamlit
releases. Less control over radius and density, and it still needs a deliberate
layer or it looks like default Streamlit.

**Recommended: B as the surface, C as the mechanism, A as the discipline.**
One token file is the single source of truth; the Streamlit theme and the CSS
variables are both generated from it; a test asserts every text pair meets
4.5:1 and every boundary 3:1 in CI, so the audit cannot regress.

## Resolution

All fifteen findings were fixed in one pass, taking the recommended route:
light-first reading surface, colours owned by the Streamlit theme, a thin CSS
layer, and tests so the audit cannot regress. Verified by measurement and by
screenshot in both modes, not by reading the stylesheet.

| Finding | Fix | Evidence |
|---|---|---|
| 1 | `--text-muted` replaced by theme `textColor`/`linkColor`; the disclaimer is now body-sized text at 15.87:1 on paper | contrast test, screenshot |
| 2 | `borderColor` is `#8f887a` light and `#6b7787` dark, 3.04:1 and 3.63:1 worst case | contrast test |
| 3 | Em dashes removed from `DOCUMENT_SOURCES`, both card sets and the excerpt renderer; a test now fails on any em dash in rendered text or config copy | `test_app.py` |
| 4 | `header` is no longer hidden; `client.toolbarMode = "minimal"` removes the Deploy button instead, so the sidebar toggle survives on narrow screens | config.toml |
| 5 | Every emoji removed from UI copy and card/section titles | `test_app.py`, screenshot |
| 6 | Labels go from 0.62 to 0.78rem up to 0.75 to 0.9375rem; body stays 1rem; mono no longer used for micro-labels | `app.css` |
| 7 | Accent now belongs to the theme and appears on interactive elements only; the CSS holds no colour at all | `test_theme_contrast.py` |
| 8 | Mono reserved for identifiers and quoted excerpts | `app.css`, `DESIGN.md` |
| 9 | Decorative status dot removed | screenshot |
| 10 | Capability cards became an index list: term carries weight, description defers | screenshot |
| 11 | Light default, dark palette declared and verified; the reader's mode picks it | both screenshots, contrast test |
| 12 | Link colour is the accent hue instead of a competing blue; blue removed from the palette | `config.toml` |
| 13 | Word-by-word streaming removed; answers render in one piece | `app.py` |
| 14 | Empty state has one focal element (the index heading) instead of four equal cards | screenshot |
| 15 | All `!important` colour overrides on buttons removed, so Streamlit's focus ring, hover and disabled styles return | `app.css` |

Measured after the change, both modes:

| Pair | Light | Dark |
|---|---|---|
| body text on background | 15.87:1 | 15.40:1 |
| link text on background | 6.05:1 | 8.48:1 |
| text on widget surface | 14.29:1 | 14.18:1 |
| border on background | 3.37:1 | 3.95:1 |
| border on widget surface | 3.04:1 | 3.63:1 |
| primary on background (focus ring, icons) | 6.05:1 | 4.45:1 |
| white label on a filled primary control | 6.30:1 | 4.03:1 |

Secondary text is size and weight, never transparency: a grey made with
`opacity` is a colour no test measures, which is how light-on-light creeps back
in. `test_theme_contrast.py` fails if the stylesheet contains `opacity` at all.

Still open by choice: a keyboard pass (Tab through every control and confirm the
focus ring visually) is a manual step this audit could not automate, and the
downloaded IBM Plex webfont degrades to the system sans if the network blocks
it.
