## Demo 1 — Current state

### Architecture

```
PDFs → pdfplumber (text + table extraction)
     → RecursiveCharacterTextSplitter (chunk_size=3500, overlap=150)
     → Groq 70B generates 5 questions per chunk (Reverse HyDE)
     → questions prepended to chunk text
     → HuggingFace embeddings (all-MiniLM-L6-v2) locally
     → ChromaDB vectorstore (vectorstore_en/)
     → At query: langdetect → Google Translate if non-English
     → expand_query() with Groq 8B generates 3 variants
     → MMR search (TOP_K=4, fetch_k=20) across all variants
     → Groq 70B answers with strict citation rules
     → Streamlit UI (not yet built)
```

### Key design decisions

**Reverse HyDE at ingest:** Each chunk gets 5 questions generated by Groq 70B.
Questions are prepended to chunk text before embedding. This solves vocabulary
mismatch between user questions and document content.

**Dual model strategy:**
- `llama-3.1-8b-instant` — query expansion (fast, simple task)
- `llama-3.3-70b-versatile` — question generation at ingest + answering (quality)

**pdfplumber over PyPDF:** Extracts tables as markdown format, preserving column
structure. Critical for 456.pdf which has Tier 1/2 consequence tables.

**Language handling:**
- langdetect detects question language
- Google Translate (deep-translator) translates non-English to English for search
- LLM answers in original question language
- MULTILINGUAL_ENABLED = False (multilingual vectorstore built but disabled —
  cross-lingual retrieval quality insufficient with current embedding model)

**Strict system prompt rules (7 rules):**
1. Use only excerpts — no general knowledge gap-filling
2. Cite every claim with source filename and page number
3. Handle prohibitions correctly (prohibition IS the answer)
4. Never hedge falsely if answer IS in excerpts
5. Keep technical terms in English even in Bahasa answers
6. Show incomplete lists honestly with note
7. Say "not found" only when genuinely not present

## Coding principles (follow always)

Based on Karpathy guidelines:

**Think before coding:**
- State assumptions explicitly before writing code
- If multiple approaches exist, present them — don't pick silently
- Check exact installed package versions before writing imports

**Simplicity first:**
- Minimum code that solves the problem
- No features beyond what was asked
- If it could be 50 lines, don't write 200

**Surgical changes:**
- Touch only what you must
- When fixing a bug, change only the broken line
- Every changed line must trace directly to the request

**Goal-driven:**
- State success criteria before implementing
- Verify each step before moving to next

## Important context for Claude Code

**Domain vocabulary:**
- IOGP = International Association of Oil & Gas Producers
- JIP33 = Joint Industry Programme 33 (standardized procurement specs)
- LOPC = Loss of Primary Containment
- PSE = Process Safety Event
- Tier 1/2/3/4 = process safety KPI tiers (456.pdf)
- Life-Saving Rules = 9 mandatory IOGP safety rules (459.pdf)
- TRS = Technical Requirements Specification
- QRS = Quality Requirements Specification
- IRS = Information Requirements Specification
- PDS = Product Data Sheet
- EPCI = Engineering, Procurement, Construction, Installation
- GR/GI = Goods Receipt / Goods Issue (SAP terminology)
- DDR = Daily Drilling Report
- AFE = Authorization for Expenditure
- WBS = Work Breakdown Structure
- PTK-007 = SKK Migas procurement guidelines

**Target users (3 personas):**
1. Site/HSE Engineer — needs fast answers on safety procedures
2. Procurement Engineer — needs JIP33 spec compliance answers
3. IT/Digital Champion — evaluating AI for their O&G organization

**Non-negotiable constraints:**
- Zero API cost (Groq free tier only)
- No INPEX branding or references anywhere
- No confidential data — all documents are public IOGP standards
- Answers must cite source document and page number
- Never hallucinate — "not found" is better than wrong answer
